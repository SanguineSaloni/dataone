DataOne × Databricks — modularization brief · 2026-07-27

Modularize once, swap backends forever

A reflection of the ask behind DATABRICKS_NATIVE_ASSESSMENT.md, turned into a concrete module boundary — plus the exact points I need you to confirm before any code moves.

01Refined prompt

"Share the design to modularize this existing changes that can be leveraged AS IS and Databricks Native."

Here's what I understand you're asking for — not the Phase 1/2/3 rewrite roadmap the assessment already lays out, but the architectural precondition for it: split every capability DataOne owns today into a stable interface plus two implementations behind it —

  • AS-IS module — today's working code (in-process query exec, Celery pipelines, app-owned catalog, local JWT), untouched, just moved behind an interface it doesn't currently have.
  • Databricks-native module — a new, additive sibling implementation (SQL Warehouse exec, Spark/Delta push-down, Unity Catalog reader, workspace OAuth) selected at runtime per source/tenant, never replacing the AS-IS path.

The point: DataOne keeps serving Postgres/MySQL/Oracle customers exactly as it does today, while a Databricks-connected customer gets the native path — same UI, same routers, same agentic-DBA/mapper/autopilot layer on top, different card plugged into the same slot underneath.

Confirm before I draft interfaces
  1. Scope for this pass — all 7 capability rows below, or just Connectors + Query Execution (the low-risk Rung A slice)?
  2. Selection mechanism — per-connector config (a source is "Databricks" → native path auto-selected), or a workspace/tenant-level mode flag?
  3. Interface style — Python Protocol/ABC extracted now with only the AS-IS implementation behind it (Databricks side stubbed/deferred), or wait and design the interface once the Databricks side is being built?
  4. Non-negotiable — should the multi-source fallback (§7.3 of the assessment) be a hard constraint on every interface, i.e. no interface may assume Databricks-only fields?

03Module rack — one slot per capability

AS-IS — kept exactly as it runs today Databricks-native — new sibling module
ConnectorsM · 2–4 pw · additive only
AS-ISbackend/app/connectors/

psycopg2 / pymysql / oracledb / sqlite3 drivers, registered in connector_catalog.py. No changes.

Native — newbackend/app/connectors/databricks.py

New BaseConnector implementation on databricks-sql-connector; registers alongside existing types, same catalog file.

Query executionM · 3–5 pw · depends on Connectors
AS-ISquery_execution_service.py

DB-API fetchall() in a thread pool, 30s timeout, 5000-row cap. Stays the path for every non-Databricks source.

Native — newquery_execution_service_databricks.py

Async SQL Warehouse statement submission + chunked fetch. Selected only when the source connector is Databricks.

Pipelines / ETLXL · 8–14 pw · largest rewrite
AS-ISpipeline_executor.py, transformation_grammar.py

In-process row batching + per-row Python transform, unchanged for OLTP-to-OLTP pipelines.

Native — newpipeline_executor_spark.py

Grammar becomes a Spark SQL / MERGE / DLT-spec code-gen target; lands in Delta under Unity Catalog.

Catalog / lineage / classificationM–L · 4–7 pw · dual-mode by design
AS-ISschema_catalog_service.py, profiling_enrichment.py, diff_service.py

App-owned catalog in Postgres — the permanent fallback for every non-Databricks source, not a bridge to delete later.

Native — newcatalog_service_unity.py

Reads UC information_schema + lineage API; mirrors UC tags into DataOne classifications rather than duplicating scoring logic.

Orchestration / schedulingL · 5–8 pw · depends on Query exec
AS-IScelery_app.py, scheduler.py

Keeps owning every app-tier async task (suggestions, health checks, audit flush) — no change in scope.

Native — neworchestration_workflows.py

scheduler.py becomes a thin submitter to Databricks Workflows/Jobs SDK for data-plane runs only; polls job state back in.

Auth / identity / tenancyL–XL · 6–12 pw · highest risk
AS-ISrbac_service.py

Local HS256 JWT + 3-role RBAC stays the entire auth model in standalone mode. Untouched.

Native — newauth_workspace_oauth.py

Workspace OAuth / on-behalf-of identity, only inside Databricks-App mode; maps UC grants → DataOne roles — needs security sign-off before this ships (§9 [!] in the assessment).

LLM inferenceS · 1–2 pw · already one swap point
AS-ISai_service.py

get_ollama_url() behind a circuit breaker — the interface essentially already exists here.

Native — newai_service.py (provider branch)

Add a DATABRICKS_SERVING provider option in the same file via Settings; nothing above AIService changes.
